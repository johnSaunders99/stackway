## 為什麼要學：放得下，不等於算得快
同一模型提供半精度與好幾個量化檔，下載頁上最小的那份很誘人。但「小」回答的是儲存問題，還沒回答你的卡能不能用那條計算路徑，也沒說模型仍能否答對。量化（quantization）是用較少的表示值去近似原數值。本課先做一筆能核對的位元組帳，再選一個值得上機驗證的候選。

## 核心概念：整數之外還有刻度
半精度浮點（FP16）每個權重佔 16 位元；8 位元整數（INT8）可用 8 位元表示一個量化值；4 位元整數（INT4）理想緊密封裝時 2 個值佔 1 位元組。用較短的編碼就像把尺的刻度變粗：原來不同的兩個權重可能落在同一格，超過表示範圍的值也可能被截去。

要把整數還原成近似權重，還需要比例因子（scale）。例如某組用 0.1 為一步，整數 3 代表約 0.3，不是浮點數 3。按組設定刻度較能照顧數值範圍不同的區段，但組越小，需存的刻度越多。有些格式還另存零點，且要遵守封裝與對齊要求。看到「4 位元」不可直接斷言整份模型恰為原檔 1/4。

## 範例：把刻度獨立列在帳上
在 `C:\dev\stackway-lab\serving` 新建 `quant_bytes.py`。把理想的權重位元數換成位元組，另列格式額外需要的資訊。縮小檔案不等於一定縮短服務延遲。

在該目錄執行：Windows PowerShell 用 `py quant_bytes.py`；macOS／Linux 用 `python3 quant_bytes.py`。

```python
from math import ceil
n, group = 1024, 64
for name, bits in [("FP16",16), ("INT8",8), ("INT4",4)]:
    payload = ceil(n * bits / 8)
    scales = 0 if name == "FP16" else ceil(n/group)*2
    print(name, payload, scales, payload+scales)
```

這是對稱分組的教具，忽略標頭及對齊；每組 64 個元素，刻度用 2 位元組，浮點基線不另存刻度。先比較純資料欄，再比較最後一欄。把組長縮半，不動權重數和位寬，兩種整數格式的附加欄都會變大。若把結果和磁碟檔比，碰到差異時，回頭查哪些層未量化、檔案還存了什麼，而非調整算式硬湊。

### 正確的刻度也可能讓任務翻盤
在紙上選兩個很接近的候選分數，原本較高者勝出。若量化讓兩者落進同一格，回推之後就看不出原來的細微差異。不是每次捨入都會改答案，但接近決策邊界的輸入值得特別抽查。除了代表多數情形的普通題，將容易混淆的欄位與容易遺漏的短答案各留幾題，並在調整格式之前寫好判分規則，才知道省下空間的代價出現在哪裡。

## 常見錯誤
把權重量化與鍵值快取量化視為同一件事；只有明確設定改變的部分才能算入節省。支援讀取某個檔也未必有高效運算核心，解封裝、轉型、輸入長度及並行度都會影響實際耗時。支援表應看具體量化方法、裝置世代與後端組合，不把 INT4 三個字當作相容保證。

## 小結
先用容量和硬體條件縮小候選，再拿固定評估集比較輸出品質與速度。若任務是抽欄位，驗收就應比哪些欄位抽對、哪些漏掉，而不是挑一段看起來很通順的回答當通過。保留原精度基線，才能知道換來的空間值不值得。
