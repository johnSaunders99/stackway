## 為什麼要學：昨天的模型怎麼知道明天的事？
你想用歷史工作量預測隔天壅塞。若整理資料時先讀完包括未來在內的全部紀錄，連「平均一天有幾件事」都已藏著未來資訊。資料洩漏（data leakage）指的是訓練或選擇模型時，用上了在真正預測當下不可能取得的資訊。分數也許變漂亮，卻不再回答「明天能不能用」。

## 核心概念：3 份資料，3 種權限
訓練集（training set）用來從資料學習參數，也用來決定前處理需要的統計量。驗證集（validation set）讓你比較候選設定，例如選哪個警示門檻；測試集（test set）保留到決策結束，給最後一次獨立評估。測試集不是不能碰的展示品，而是不能反過來指導你反覆調整的方法。不斷看它再改模型，就把它當成另一份驗證集了。

切分方式要模擬實際使用。預測未來的工作量時，本例按時間順序切：較早的日子訓練、中段驗證、最後測試。若任務是辨認新機器的行為，可能要按機器分組，避免同一機器近乎重複的紀錄同時出現在兩邊。不是隨便把比例湊對就完成；要先說出評估究竟在模擬哪一種「沒看過」。

## 範例：只改未來資料，昨天的轉換不應改變
在 `ml-notes` 新增 `split.py`，只用 Python 標準函式庫。PowerShell 執行 `py split.py`，bash 執行 `python3 split.py`。數字已依日期由早到晚排列，扣除平均值是為了示範前處理：先用訓練集求出中心，再用同一中心轉換所有分組。
```python
from statistics import mean

def inspect(days):
    train, valid, test = days[:4], days[4:6], days[6:]
    center = mean(train)
    return center, [v - center for v in valid], mean(days), len(test)

for last in (24, 240):
    rows = [8, 10, 12, 10, 14, 16, 20, last]
    print(inspect(rows))
```
前 4 天平均為 10，因此驗證集都得到 4、6。第三個輸出故意列出錯誤做法的中心，只供這個教學對照，不用於模型。最後一天從 24 改成 240，若訓練轉換也跟著移動，正好證明它讀過未來。這個實驗不需要訓練模型，也不靠「分數一定會變高」來判斷有沒有洩漏。

### 驗證資料為什麼不用自己的平均
將來服務剛收到第一筆新工作時，不會先擁有完整的未來 1 週可供計算。把訓練時的中心一併保存，部署後套用同一個轉換，才讓驗證時看見的數字與真正使用時的處理方法相同。

## 常見錯誤
先在整份資料補缺值、算平均，再切訓練與測試；即使模型最後只收到訓練列，前面那個平均值已經帶入其他列的資訊。另一個容易忽略的例子是想在工作送出時預測是否逾時，卻把「實際完成時間」當輸入；再完美的分組都救不了一個當時不存在的欄位。先在每個欄位旁註記它何時可得。

## 小結
一份可信的切分紀錄該說清楚資料的時間範圍、各組的用途，以及每個前處理參數從哪組學出。最後反問：「若未來資料完全換掉，過去的訓練程序應該保持哪些結果？」這比只背切分比例更能幫你找錯。
