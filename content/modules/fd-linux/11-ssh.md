## 為什麼要學：加密連線也要先問對面是誰
你有權進入教學用的遠端主機。第一次連線時，終端機沒有直接顯示遠端提示字元，而是問是否信任一把主機金鑰。若你只是照習慣按確定，加密通道也可能通到錯的機器。沒有授權主機的人這堂不必連線：同樣可以用一對記錄卡練習何時繼續、何時停下來，以及事後怎樣標明指令究竟在哪台機器執行。

## 核心概念：主機向你證明身分，你再向主機證明身分
安全殼層（Secure Shell，SSH）讓本機用戶端透過加密連線在遠端執行命令。主機公開金鑰的指紋（host key fingerprint）是從金鑰算出的識別摘要。第一次連線，要用管理方**事先由另一個可信管道**提供的指紋，比對同一把金鑰的演算法與完整摘要。連線畫面自己提供的字串不算第二份獨立證據。比對成功並接受後，用戶端通常會在已知主機紀錄（known hosts）留存這把公開金鑰，供以後辨識變動。

使用者金鑰（user key）回答的是另一個方向的問題：由你在本機持有私密金鑰，對挑戰提供簽章，遠端可用已授權的公開金鑰驗證。不需要把私鑰交給遠端保管。使用者驗證成功也不能倒過來證明第一次遇到的主機必定正確；把兩個問題分開寫，遇到錯誤訊息才知道要找誰核對。

## 範例：不借用任何真實主機也能練判讀
Windows 在 PowerShell 的 `C:\dev\stackway-lab`，macOS 或 Linux 在本機終端機任一練習目錄。以下只查本機用戶端的版本，不讀私鑰、不嘗試登入，也不會建立遠端工作階段。找不到工具時直接做下方的紙上判讀。

```powershell
ssh -V
```

準備兩欄，左邊寫「管理方提供：演算法相同、指紋代號甲」，右邊第一次填「連線畫面：指紋代號甲」，第二次改填乙。代號只是教學索引，不是真正能比對的指紋。第一張在來源獨立、完整值相符而且使用目的已授權時才能繼續；第二張要停下來查證，不能拿「主機名稱相同」當替代證據。重裝或輪替金鑰可能造成真變更，未查證前不能把某一種原因寫成定論。

已有專用教學主機且取得登入許可時，向管理方取得連線目的地與可信指紋，只在自己的終端機使用它們，不把帳號或位址放進練習單。互動登入後用遠端的 `pwd` 讀工作目錄，再 `exit` 回本機。Windows 用 `Get-Location`，macOS 或 Linux 用 `pwd` 讀本機位置。兩側就算碰巧顯示相同文字，也是不同的 shell；提示字元漂亮與否不是證明。沒有主機時依序畫「本機 → 核對主機 → 遠端 → 離開 → 本機」，可取代實際登入。

## 常見錯誤
把主機識別警告當成登入密碼打錯，重試也不會回答「對面是誰」。別因指紋變動就刪除已知主機紀錄、停用檢查或把私鑰貼給別人；先向負責人以可信管道確認變更。紀錄裡只需要留下判斷與執行邊界，不用存放連線憑證或可識別個人的資料。

## 小結
交付兩個決定：「甲在什麼條件下可繼續」、「乙為什麼要停」，再用箭頭標出本機與遠端。判斷做對，比把陌生機器連通更重要；沒有登入的練習也能驗收這項能力。
