## 為什麼同一張格子圖會算出 2 個答案？
從左上走到右下，每一步只能往右或往下，不可踩障礙。有個人回答最短步數，另一個人回答可行路徑數。兩人都畫了一張表，格子的意義卻不同。我們要求路徑數，不能用取較小值來合併來源。和前一堂階梯題相比，多一個維度不是因為問題比較「高級」，而是只給列或只給欄都不足以辨認所在的位置。

## 最後一步必定來自上方或左方
定義 `ways[r][c]` 為從起點恰好抵達第 r 列第 c 欄的路徑數。起點若可通行就有 1 種空走法；遇到障礙一律是 0。對其餘可走的格子，最後一步只能由正上方往下或正左方往右，兩群路徑不重疊，因此把來源相加。邊界外沒有格子，當 0 處理。逐列由上到下，每列由左到右，讀來源時 2 個值都已經確定。

一個小技巧是先把所有格子填 0，再只在合法來源存在時加進去。不要在第一列或第一欄整排填 1：一旦路上有牆，牆後面未必能到達。另一方面，也不能說牆右邊永遠到不了；若牆不在第一列，可能從上方繞過來。格子要看直接來源，而不是僅看同一條線上是否曾出現障礙。

## 範例：讓每一列都印出來
在 `C:\dev\stackway-lab\coding` 存 `grid.py`，執行 `py grid.py`；macOS／Linux 用 `python3 grid.py`。這裡約定輸入是非空長方形，句點能走，星號是牆。

```python
def paths(board):
    h, w = len(board), len(board[0])
    ways = [[0] * w for _ in range(h)]
    for r in range(h):
        for c in range(w):
            if board[r][c] == "*":
                continue
            if r == c == 0:
                ways[r][c] = 1
            else:
                ways[r][c] = ((ways[r-1][c] if r else 0)
                              + (ways[r][c-1] if c else 0))
    return ways

for row in paths(["...", ".*.", "..."]):
    print(row)
```

目的地有 2 條路，沿上邊再下來，或沿左邊再向右。若移走中間的牆，中心會有 2 條路，底部中間和右側中間各有 3 條，終點便是 6。這個對照比只記住一個最後數字更有用：如果移走障礙後整個第一列都變了，錯誤不在終點，而在表格的建立或更新方式。

### 用一列格子測邊界
把棋盤縮成一列 3 格，先只堵住中間，然後把牆移到末端。前者走到第一格就停，後者能走到第二格，2 次終點都為 0；只看終點分不出轉移是否正確。這就是保留整張小表的好處：兩次輸出應只有特定格子改變。如果第一格也跟著變化，先回頭檢查起點定義，不必急著懷疑遞推公式本身。

## 常見錯誤
Python 的負索引會從尾端取值，靠例外處理抓不到「讀到第負一欄」的錯。請明確判斷邊界。用同一個內層串列複製多次也會讓多列共用一份資料；改一列，別列跟著變。延伸練習的正式題目要求對指定整數取餘數，本範例只用小尺寸解釋計數，並不是競賽輸入輸出的完整提交。

先在手算的小格子標出起點與障礙，再畫合法來源方向；若起點本身不能走，就不該憑空產生第一條路。

## 小結
先確定每個座標代表一個什麼答案，再看它最後一步能從哪裡來。逐格法對每格做固定數量的加法；表的大小是列數乘欄數，保留表也讓你的障礙案例能逐格驗算。
