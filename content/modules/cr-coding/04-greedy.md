## 同一間放映室要看最多場，先進場就贏嗎？
可選時段是從 1 到 9、從 2 到 4、從 4 到 6、從 6 到 8。若看最早開演的一場，就只看得到 1 場；跳過它反而能看完 3 場。上一堂把相交時段合併，是為了保留全部覆蓋範圍；這一堂是從中挑一部分，讓完整參加的場次最多。即使輸入格式一模一樣，排序依據也可能完全不同。

## 先挑最早讓出座位的那場
貪婪法 (greedy algorithm) 每一步做一個不回頭的選擇。先按結束時間遞增排序，挑第一個能參加的場次，再從它的結束點繼續。半開區間約定不變，下一場起點等於上一場終點可以接上。選最早結束並不是因為那一場本身最短，而是它把下一次可開始的時刻推得最少。

要說服別人，想像手上已有一份最多場次的排程。它的第一場如果不是我們挑的那場，把它換成我們的第一場。換過來的結束時間不晚於原本，所以原排程第二場以後仍能照常進場，場數也沒變。於是在所有最佳解之中，至少有一份可以用我們的第一步開頭。拿掉第一場，在剩下相容的時段重做同一個論證。這叫交換論證 (exchange argument)，比「測了好多次都對」更有說服力。

## 範例：先報選了什麼，再報有幾場
在 `C:\dev\stackway-lab\coding` 存 `festival.py`，執行 `py festival.py`；macOS／Linux 用 `python3 festival.py`。保留被挑中的場次，方便別人驗證它們真的接得上。

```python
def schedule(shows):
    chosen = []
    for start, end in sorted(shows, key=lambda s: s[1]):
        if not chosen or start >= chosen[-1][1]:
            chosen.append((start, end))
    return chosen

print(schedule([(1, 9), (2, 4), (4, 6), (6, 8)]))
```

也來檢查「挑最短」的直覺。時段從 0 到 4、從 4 到 8、從 3 到 5，長度最短的中間場跨過交接點，一次擋掉兩場，最早結束卻能留下相接的兩場。反例不必很大，只要讓兩個策略做出不同的第一步，而且你能算出哪邊較好。

### 若兩場同時結束，選誰有差嗎？
在各場等值、切換不需時間的約定下，兩場都能接上前一場，又在同一時刻結束，留給後面的時間便相同；任選其一不會改變最大場數。若測試只接受某一份固定清單，就可能把另一份合法最佳解判錯。可以檢查選中的數量與合法性，或和需求方另訂同分時的排序規則。這樣做不是補證明，而是分清「求最大場數」和「回傳唯一排程」是兩個不同的契約。

## 常見錯誤
本題每場都算 1 分，若每場票價或學分不同，最大總價不是最大場數。可能有一場長活動比所有短活動加起來都值錢，這時交換後雖保住場數，卻不一定保住價值。不應沿用原證明。若問題再加上跨館移動時間，也必須把移動規則放進能否接場的條件。

試著把你選的項目換進另一個可行解，說明後續仍能完成哪些選擇。舉出一次成功案例還不算證明。

## 小結
排序耗時 O(n log n)，挑場只走一次。能否用貪婪法，取決於你能不能換掉最佳解的一步而不變差；先說出「好」指場數還是價值，再談選擇規則。
