## 「找出重複」究竟要交什麼？
面試官給你一列編號，請你找出重複。你打算回傳一個編號，對方卻準備拿整數比答案。即使程式每一行都正確，兩邊其實在做不同題。澄清不是把面試官的每個字再唸一次，而是找出哪個尚未決定的規則會改變輸出。先帶入一個很小、但能讓兩種規則給出不同答案的輸入。

## 用反例換到可以動手的契約
輸入 `[7, 7, 7]` 時，「出現過重複的編號有幾種」是 1，「第一筆以外又出現幾次」是 2，「值相等且位置不同的配對有幾組」卻是 3。這比詢問「重複算嗎」好，因為對方可以直接選一個答案。本題約定求配對數；位置沒有先後之分，同一個位置不能配自己。再問輸入大小、是否已排序、可不可以改動原資料。若只會拿到幾十筆，透明的做法可能已足夠；若可能有 10 10000 筆，才有理由追求更少比較。

基準解 (baseline) 的任務是先給一個可信的對照，不是故意寫一個錯解等面試官修。用左位置固定第一筆，右位置只走它後面。這個範圍同時保證不會自己配自己，也不會把同一對反過來再數一次。你可以把迴圈想成畫一張方格表，只檢查對角線右上角。

## 範例：讓索引對替你作證
為限時解題的原始版本建立 `C:\dev\stackway-lab\coding`。存入 `pairs.py`，執行 `py pairs.py`；macOS／Linux 用 `python3 pairs.py`。先用紙列出索引對，再對照結果。

```python
def pairs(values):
    return sum(values[i] == values[j]
               for i in range(len(values))
               for j in range(i + 1, len(values)))

for row in ([], [7], [7, 7, 7], [1, 7, 1, 7]):
    print(row, pairs(row))
```

布林值在加總時，成立貢獻 1，不成立貢獻 0。最後一列的合法索引對是第 0 與 2 位、第 1 與 3 位，不必相鄰。長度是 n 就會比 n(n−1)/2 次，時間複雜度為 O(n²)，額外空間為 O(1)，因為這裡用的是逐項取值的產生器，沒有存起全部索引對。若只改成把每次比較都留下，時間相同，空間卻會改變。

### 把問題問到剛剛好
若對方說值已排序，而且只要配對總數，可以一段段處理相同編號：連續有 4 個相同值，第一個可配後面 3 個、第二個可配後面 2 個、第三個可配最後一個，總共 6 對。反過來，若對方要交出每一對的位置，不論如何加速計數，都省不掉列出每一對的輸出成本。「要數量還是要明細」因此比先問偏愛哪種程式語言更能改變你的解法。

## 常見錯誤
看見「重複」就先轉成集合，會失去每個值原本出現幾次。想改快時，先說明保留的是哪一項資訊：掃到一個值時，每一筆先前出現的相同值都能各組成一對。先加先前的次數，再把目前這筆記進去；順序倒過來就會把自己也配進答案。保留慢版，讓小輸入可以驗證這個改動。

## 小結
一個好問題能換到可檢查的答案：先列出相同輸入的不同解讀，選定規則，再寫不漏不重的基準解。面試裡可以暫時很慢，不要在沒說明的情況下做成另一題。
