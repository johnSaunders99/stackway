## 遞迴明明會算，為什麼還要填表？
一座階梯每次可以走 1 階或 2 階，想知道剛好走到頂端有多少種走法。從第 5 階往回問，最後一步不是從第 4 階跨來，就是從第 3 階跨來；但在求第 4 階時，你又會問一次第 3 階。重疊子問題 (overlapping subproblems) 的意思是不同呼叫正在索取同一個答案，不是 2 條走法被題目當成同一條。

## 一格代表什麼，先用完整句說出來
動態規劃 (dynamic programming) 會保留子問題答案供重用。定義 `dp[i]` 為「從地面出發，恰好走到第 i 階的有序走法數」。它不是最少步數，也不是曾經經過此階的次數。最後一步跨 1 或跨 2 不會同時發生，兩群走法互不重疊；把最後一步拿掉，前半段又剛好是對應格子已經數過的走法。因此從第 2 階起，答案是前面 2 格的和。

初值最好用故事決定。高度為 0，不採取任何一步就恰好在目標，空走法算 1 種。到第 1 階只能走一步，所以也是 1。若把 0 階設成 0，唯一那種直接跨 2 階的走法就沒了。這和無法到達的格子不同：前者有 1 個空序列；後者連空序列都不能滿足目的地。

## 範例：填完的每一格都是測試資料
在 `C:\dev\stackway-lab\coding` 建立 `stairs.py`，執行 `py stairs.py`；macOS／Linux 用 `python3 stairs.py`。只接受非負整數高度，負數只在參考遞迴裡表示不可能的前一步。

```python
def slow(n):
    if n < 0:
        return 0
    if n == 0:
        return 1
    return slow(n - 1) + slow(n - 2)

def table(n):
    counts = [1] * (n + 1)
    for i in range(2, n + 1):
        counts[i] = counts[i - 1] + counts[i - 2]
    return counts

row = table(6)
assert row == [slow(i) for i in range(7)]
print(row)
```

第 3 階有「一步再 2 步」、「2 步再一步」、「連走 3 個一步」，所以表中是 3 而非 2。把 2 步的順序交換可能形成不同路線，這決定了你能不能把兩群答案相加。填表由小到大，是因為每格只讀已經定案的較小高度，不是所有動態規劃都非得從左往右填。

### 不靠數列名稱做一次變形
若樓梯規定只能走一步或 3 步，把第 6 階的合法走法拆開：最後走一步的來自第 5 階，最後走 3 步的來自第 3 階。再看第 2 階，還不能用 3 步，只剩連走 2 個一步。這說明改公式時也要重看前幾格；把原本整張表預填成同一個值，不能替所有新規則決定邊界。先標出哪些來源真的存在，再讓對照遞迴替這些小格核對一次。

## 常見錯誤
把陣列長度設成高度本身，就沒有索引放終點；又或者為了設定第一階而在高度為 0 時硬寫第二個格子。先跑 0 階可以抓到這兩個問題。只需要最後一個數量時可以省成 2 格，但面試一開始就壓縮，很容易弄混更新先後。先保留整列表，用手算對上前 3 格，再討論如何節省空間。

先解釋空起點代表的那一種方法，再填下一格。基底是對問題的定義，不是為了讓範例數字好看才放進去。

## 小結
用狀態句、初值、最後一步與計算順序講完解法。填表做線性次數的加法，樸素遞迴只適合小輸入當對照。延伸題把步長改成骰子的 1 到 6 時，先換掉最後一步的候選集合，而不是照抄原公式。
