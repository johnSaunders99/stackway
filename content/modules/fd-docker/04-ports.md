## 為什麼要學：服務醒了，瀏覽器怎麼找它？
容器的紀錄說伺服器已經啟動，你在自己的瀏覽器輸入同一個連接埠，卻連不到。服務其實可能完全正常。容器有自己的網路空間；主機（host）是你執行 Docker 的電腦。瀏覽器問的是主機，而網頁程式在另一個空間等連線。必須交代這條路的入口和終點，不能只說「它在跑」。

## 核心概念：把映射念成一句話
連接埠（port）是同一位址上用來分辨服務的號碼。發布（publish）時寫 `-p 127.0.0.1:8080:80`，從左往右是「只在主機的回送位址接收，入口為 8080，轉到容器的 80」。回送位址（loopback）指向自己；選它是因為這個服務只給坐在本機前的你測試。主機與容器的號碼不必相同，而且改入口不會改動容器內的程式設定。

容器內也有「自己」。若自行寫的伺服器只聽容器內的回送位址，它不會接收從容器網路介面進來的流量。容器內聽所需介面，和主機端只開放回送位址並不矛盾：前者讓轉送有終點，後者限制入口。這次使用已經設定好內部監聽的官方網頁映像，把變因縮小為入口選擇。

## 範例：從瀏覽器一路讀到服務
請使用目前支援的本機引擎；本例要求 Engine 28.0.0 以上，舊版的本機發布有同網段仍可能連到的例外。若無法核對版本，就只畫路徑，不啟動服務。確認實驗名稱尚未使用，再在任意資料夾的 PowerShell 或 bash 執行：
```powershell
docker run -d --name sw-port-demo -p 127.0.0.1:18080:80 nginx:alpine
docker port sw-port-demo
```
`-d` 表示背景執行。應看到容器的 `80/tcp` 對到主機 `127.0.0.1:18080`；紀錄列印的順序和輸入參數不同，認準數字旁的位址。到瀏覽器網址列輸入 `127.0.0.1:18080`，看到歡迎頁，就把入口到終點的路徑寫下。看完用 `docker stop sw-port-demo` 停止，確認是本課自己建立的容器，再用 `docker rm sw-port-demo` 收尾。

### 一個埠衝突的紙上推演
假設還要開第二個一模一樣的測試頁。兩個服務都能在各自容器的 80 監聽，因為它們沒有共用同一個網路空間；但兩個主機入口不能同時占用同一位址的同一個埠。畫兩條箭頭，左邊分別寫上不同的主機埠，右邊各寫對應容器的 80。此時只看右側數字分不出你打開哪一頁，必須連同主機入口與容器身分一起讀。

## 常見錯誤
主機埠被占用時，不需要停止不認識的程式。改選未使用的入口，如 18081，保留右側 80；若先前失敗的建立動作已保留名稱，就換新的實驗名。只在 Dockerfile 裡寫 `EXPOSE` 是說明預期埠號，不會建立主機入口。反過來，省略 `127.0.0.1` 並不是更簡潔的等價寫法，預設可能在其他網路介面也接受連線。

## 小結
判斷「不通」時依序問：瀏覽器在哪裡、它用的是哪個入口、入口後面是哪個埠、程式有沒有在那裡聽。這四個答案比反覆換瀏覽器更有用。
