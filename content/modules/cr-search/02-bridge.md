## 為什麼要學：相同工具不等於相同工作

你用 Python 做過失敗報表重跑工具；職缺要維護後端匯出服務。只說「我也會 Python」，招募方不知道你能不能處理重複工作或壞資料。職務橋接（skills mapping）要做的是把你處理過的問題，連到職務每天真的要做的事，同時把仍缺的現場經驗留下來。兩邊工具不同，問題的結構反而可能相同。

## 核心概念：一列只接一個工作動詞

從職缺抄下動詞和受詞，例如「定位匯出失敗」。第二欄換成你做過的可觀察動作：「保留失敗列的輸入代號與原因，修正資料後只重跑這列。」第三欄放能打開的證據，例如測試紀錄，不要只放專案首頁。最後才標示距離：已直接展示、相近但條件較小，或尚無證據。中間那類特別有用，因為它指出你可以怎麼轉移能力，而不是只有會或不會。

把同個專案放到平台職位，動詞要重新選。「維護批次任務」在意的是能否發現失敗、重新執行、避免重複產出；「回應跨團隊夜間故障」還包括告警接手、溝通和時限。你可以用本機重跑證明前半段，不能靠一張成功截圖補出後半段。讓對方看得見你的起點，比把層級寫大更容易接著討論入職後如何上手。

## 範例：用一份小證據接 2 種職缺

在 `C:\dev\stackway-lab` 的新資料夾 `bridge-demo` 建立 `check_rows.py`，於該處執行 `py check_rows.py`；macOS 或 Linux 用 `python3 check_rows.py`。想像這是你作品裡最小的一段，先搞清楚它真的展示了什麼。

```python
rows = [("r1", "12"), ("r2", "?")]
for key, raw in rows:
    try:
        print(key, "ok", int(raw))
    except ValueError:
        print(key, "invalid integer")
```

後端職務可以對到「逐列驗證輸入，回報哪筆欄位錯誤」：畫面同時有成功與失敗。平台職務可以對到「見到錯誤時能依代號縮小排查範圍」；這只是橋接證據，因為程式沒發送告警，也沒展示在多台機器上重跑。把問號改為 8 再執行，會看到那列變成成功；這是修正資料後全批重跑，不能描述成已實作單筆重試。

### 選最短的下一段

若兩個職位都反覆要求「只補跑失敗資料」，補一份接受失敗代號清單的小測試，比再做一個首頁更接近缺口。成功條件可以是第二次輸出只包含 r2，原本成功的 r1 不再處理。如果要求的是有正式輪值經驗，就把它列成現場經驗缺口；練習可以讓你準備討論失敗，卻不能製造已經值過班的事實。

## 常見錯誤

把課名和職缺關鍵字連成直線，例如「上過容器課，所以有生產環境經驗」。課程可以支持學習背景，不能代替具有環境和結果的案例。另一個誤判是把工作完全對不到視為自己什麼都不會。先把證據縮到可驗收的那一步，再寫下為什麼離真正的職責還有一段距離。

## 小結

一條有力的橋接句讀起來像：「你們要做甲，我在條件乙做過其中的丙，可以用丁驗證；還沒有證明的是戊。」能指出界線，才知道下一個練習要花在哪裡。
