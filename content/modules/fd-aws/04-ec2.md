## 為什麼要學：關掉主機，明早還能接著做嗎？

把筆記存在正在執行的程式、主機附帶的暫存空間或獨立磁碟，現在看起來都打得開，等主機停止才會發現差別。Amazon EC2 提供運算執行個體（instance）。本課只研究使用 EBS 根磁碟的一般隨需主機與普通停止，不討論休眠、預留承諾或特殊機型計費，也不要求你去主控台實際按停止。

## 核心概念：樣板、機器、裝在機器上的磁碟

機器映像（Amazon Machine Image，AMI）描述用什麼啟動新主機，例如作業系統與預裝軟體；執行個體是從樣板配置出來的個別主機；區塊儲存磁碟區（EBS volume）則保存寫入的資料。啟動後才更改的檔案不會逆向更新原映像。若要保留某個時點的磁碟內容，可做快照（snapshot），但仍要驗證能否還原成可用資料。

停止（stop）讓這台主機不再提供運算，之後可重新啟動同一執行個體；一般停止不保留記憶體，執行個體儲存（instance store）的內容也不應指望留下。EBS 磁碟仍在，配置容量仍可能計費。自動配發的公有 IPv4 重新啟動後通常不同；不要把它寫死為永久入口。終止（terminate）則不能再啟動同一台；每個附掛磁碟是否一起刪除，要看各自的終止時刪除設定。

## 範例：把 3 種生命週期拆成可勾選清單

在 `C:\dev\stackway-lab\aws` 存 `machine.py`，用 `py machine.py` 執行；macOS／Linux 用 `python3 machine.py`。名稱和設定完全虛構。先猜普通停止時兩顆磁碟會留哪幾顆，再看結果；第二種情境才會讀取刪除旗標。

```python
volumes = {"root": True, "notes": False}  # delete on termination
for event in ["stop", "terminate"]:
    kept = [name for name, delete in volumes.items()
            if event == "stop" or not delete]
    print(event, "serving", False, "can start same instance", event == "stop",
          "EBS retained", kept)
```

只要主機不是在服務狀態，就把可用性列為中斷；不要因為資料仍可恢復就說服務仍然在線。情境 2 只留下筆記磁碟，還要有相容的新主機、正確附掛和檔案讀取驗證，才算重建完成。若兩顆都設成終止刪除，又沒有可用備份，映像不會憑空生出後來的筆記。

### 用「重建後可讀」而不是「有快照」作標準

把作業檔想成兩份：一份已明確儲存到筆記磁碟，另一份只留在編輯器尚未儲存的緩衝區。即使兩份畫面都可見，普通停止後也不能期待後者從磁碟長出來。若明天不是重啟而是更換主機，驗收要指向一份具體檔案：從保留磁碟或快照建立的副本讀出哪一版作業，大小或內容是否符合停機前的紀錄？這個問題能揭露把暫存空間誤當永久資料、快照過早，或只保存樣板沒有保存作業的差別。

## 常見錯誤與小結

「停止後一般不再計執行時數」並非「整個環境 0 元」。磁碟、快照或保留位址仍各有自己的規則。寫生命週期卡時分三行：服務能否接請求、資料留在哪裡、下一期帳單要查哪個資源。把三種答案分開，才不會為了省一晚時數而意外丟掉 1 週成果。
