## 為什麼要學：模型過了離線測試，誰承擔第 1 個錯答？

一個新模型在固定驗證集上比舊模型準，但對特別長的輸入慢了很多。直接切換所有使用者會讓每個人同時承擔這個未知風險。模型發布（model release）不只是把檔案複製到服務裡；還要決定誰看見新答案、用什麼標準判斷能否繼續，以及退回上一版時怎樣確認真的退回去了。

## 核心概念：影子看得到，使用者吃不到

影子流量（shadow traffic）把符合授權範圍的請求副本交給候選模型，使用者仍收到原版答案。這樣可以比較兩版輸出、延遲與資源消耗，但無法直接觀察使用者對新答案的反應。影子也會消耗算力；要隔離副作用，不能讓影子預測再寄一次通知、寫一筆正式訂單，或將敏感資料送給未獲准的服務。影子不是「沒有任何代價」的開關。

小比例發布（canary release）則讓少量真實流量真的收到候選答案，其餘由舊版服務。按穩定的使用者或工作單位分流，避免同一個流程前半走舊版、後半走新版。先定義觀察窗口、最低樣本、品質門檻、延遲與成本護欄（guardrails）；樣本不足時可以維持小比例繼續觀察，不能因為暫時 0 錯誤就直接放大。若有嚴重品質或穩定性問題，不必等最低樣本才停止。

## 範例：漂亮的總分不能抵銷護欄

在 `C:\dev\stackway-lab` 新建 `release-lab`，存成 `gate.py` 並於該處執行 `py gate.py`；macOS 或 Linux 用 `python3 gate.py`。候選批次的品質分數假設以相同定義和成熟標籤計算，成本用練習點數，延遲為第 95 百分位數，也就是大約 95% 的請求不超過的時間。

```python
def gate(n, quality, p95_ms, cost):
    if p95_ms > 400 or cost > .08:
        return "rollback"
    if n < 100:
        return "hold"
    return "expand" if quality >= .90 else "rollback"

for sample in [(20, .95, 310, .07), (120, .96, 510, .07), (130, .92, 320, .07)]:
    print(gate(*sample))
```

依序為維持、回復、擴大。第二批品質最好，延遲卻超過 400 毫秒的護欄。程式只是示範如何依事先約定的條件分流決策；門檻不是業界通則，且真實判斷還要在同一時段比較舊版對照組，檢查兩邊流量特徵與錯誤率。若新舊兩邊都同時變慢，還要調查共享依賴，而不是把整起事件都歸因給模型。

### 回復的是整條服務路徑

回復（rollback）至少要保存舊模型的具體版本、相容的前處理設定和路由設定；如果新版改過輸入欄位，光移回別名可能讓舊模型讀錯資料。先把新流量轉回可用舊版，再確認實際回報的版本、請求能完成、延遲與成本回到可接受範圍。已經顯示給使用者的錯答不會自動消失，要另行處理；延遲標籤也要繼續追到結果成熟。

## 常見錯誤

以為影子結果看起來相同就證明使用者更喜歡新版；沒有把答案交給使用者，自然量不到這件事。另一個陷阱是把平均成本或平均延遲拿來沖淡少數昂貴長請求的影響。保留各版本、群組與窗口的原始件數，才能在發現問題時說清楚誰受影響。

## 小結

發布前先演練退場：知道新答案目前由誰看見、哪個門檻會讓你停止，以及如何認出舊版已重新接手。能安全退一步，才有條件放心往前擴一批。
