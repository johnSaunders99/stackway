## 卡只剩一半，哪些回答寧可不給？
教學助理有兩種功能：從課文找引用段落，以及替建議題目寫較長的導讀。假如推論容量從 4 個槽掉到 2 個，把所有回答砍成半長看似公平，卻可能剛好砍掉引用出處。讀者收到很快的答案，卻無法核對。降級 (graceful degradation) 要保留任務的必要條件，而不是只保留一個成功的狀態碼。

## 先分辨可省與不可省
把功能依序寫成「最低可交付的結果、可以拿掉的裝飾、不符合時如何回應」。例：引用必須指向本次提供的文本，不能用另一版課文的快取替代；導讀可縮短，也可以暫緩。替代模型不是同義詞，它的格式、引用正確性與延遲都要先驗過。若沒有合格的替代方案，清楚表示暫時不可用，比送出不可追溯的回答更符合契約。

切換條件最好能手算。下面採一個刻意簡單的狀態機：連續 2 個觀察窗可用槽不超過 2 個，就縮短導讀；要連續 3 窗回到至少 4 槽，且引用探針都合格，才回正常。探針 (probe) 是固定輸入與可核對答案的試送。這些是演練門檻，不是所有服務共用的建議值。若單次必要品質檢查已失敗，該答案就不得送出，不必等到第二個窗。

## 範例：看見模式真的回來了
在 `C:\dev\stackway-lab\design` 存 `fallback.py` 並執行 `py fallback.py`；macOS／Linux 用 `python3 fallback.py`。每列代表一個完整觀察窗。

```python
mode, low, healthy = "full", 0, 0
for slots, probe in [(2,1),(2,1),(4,1),(4,0),(4,1),(4,1),(4,1)]:
    low = low + 1 if slots <= 2 else 0
    healthy = healthy + 1 if slots >= 4 and probe else 0
    if low >= 2:
        mode = "short"
    elif healthy >= 3:
        mode = "full"
    print(slots, healthy, mode)
```

第 2 窗進入縮短模式，第 4 窗雖有足夠容量卻沒通過探針，健康計數歸零。直到第 7 窗才回正常。兩個門檻不同是為了避免容量在邊界晃動時不斷切換。真正上線時要記下「實際走哪條服務路徑」，而非只看設定開關；設定說正常、請求卻仍使用短導讀，就是回復尚未完成。

### 用一題找出假的回復
準備一段只含某個日期的測試課文，固定問那個日期出自哪一段。正常路徑應能在指定文字中指出位置，縮短導讀也不能編造不存在的句子。測試記錄除了通過與否，保留課文版本、實際模式以及被核對的段落。如果探針只問服務在不在，回來的是快取舊答案也會被當成成功；換過課文後再問一次，才有機會看到這類殘留。

## 常見錯誤
把降級回應和完整回應混在成功率裡，會看不出多少人失去功能。拆開記錄完整、替代、明確拒絕與品質失敗，再用同一批固定問題檢查前後差異。不要靠手動改回設定就結案；若實際流量很少，計數沒有增加既不代表成功，也不代表仍在降級，要主動送探針確認。

## 小結
一份可交班的降級政策要寫得出進入線、不可犧牲的品質、退出線與實際路徑的證據。拿走容量再放回去，兩個方向都要演練。
