## 為什麼要學：先決定觀眾最後會看到什麼

給你 3 分鐘示範交班簿。如果從安裝套件開始講，再逐行唸程式碼，觀眾可能到最後都不知道接班的人得到了什麼。作品走讀（walkthrough）的目標是讓對方跟著一個使用者做完一件事。先寫出終點：「觀眾看見同一張交班單被登記兩次，清單卻只留一份。」再倒推需要哪些畫面；與這條路無關的設定頁，留給問答。

## 核心概念：把 3 分鐘留給一個可見差異

開場用約 20 秒交代角色和困擾，接著拿出很小的合成輸入。操作前先說你預期看見什麼，再讓觀眾看結果；這個順序使人能自行判斷成敗，而不是聽你事後解釋。中段留約 1 分鐘指出一個決策，例如保留工作首次出現的順序，因為接班者按記錄順序巡檢。收尾講清楚一個還沒驗證的邊界，並停下來讓對方選擇要追問哪段。

不要要求看的人同時讀一整段終端機紀錄又聽你說話。可以先圈出輸入的兩筆相同代號，再指向輸出中唯一留下的那筆。若只是把畫面放大，看不出對應關係，調大字體並不能補救。真正好的畫面往往只有幾行，但每行都參與了你要展示的變化。

## 範例：不用網路的主路徑和備援

在 `C:\dev\stackway-lab` 新建 `tour-demo`，將以下存成 `tour.py`。在該資料夾用 `py tour.py`，macOS 或 Linux 用 `python3 tour.py`。彩排時把兩行輸出用編輯器存成 `rehearsal.txt`，在檔首註記「彩排紀錄，非即時執行」。

```python
events = ["inspect", "restock", "inspect"]
print("input:", " -> ".join(events))
print("handover:", " -> ".join(dict.fromkeys(events)))
```

操作時先問：「第三筆 inspect 是新工作，還是重複登記？」本例假設代號代表同一項工作。因此輸出保留 inspect、restock 的原次序；若是不同班次的同名工作，單靠代號合併就會漏項。示範到這裡已經能引出一個有意義的設計問題，不必花時間捲過所有原始碼。如果有人想改這項假設，你可以改成用班次與代號的組合辨認工作，那是問答，不是必演橋段。

### 現場失敗時，怎麼轉場？

預先選定切換點：指令第一次無法啟動，確認所在目錄後仍失敗，就改開剛才保存的彩排紀錄。說「現在看的是先前這組輸入的輸出」，並照原先的順序指出差異。備援保住的是講解，不是證明此刻環境正常。時間充足才回頭排錯，否則就把失敗位置記下來，之後在[〈作品交接與重現〉](#/lesson/cr-portfolio-05-handoff)會細講如何補齊說明。

## 常見錯誤

只截最後的成功畫面，卻沒留下輸入或版本，對方看不出成功是什麼意思。另一個錯是以為承認示範失敗就會失去可信度，於是把錄好的結果當成現場結果展示。坦白切換並指出哪些部分仍未驗證，比臨時連上真實帳號或反覆重試更能顯示工程判斷。

## 小結

一輪彩排後把計時器停在終點，問自己：不靠旁白，畫面能不能回答開場的問題？留下那一組輸入、輸出與備援檔，再把其餘功能留給觀眾追問。
