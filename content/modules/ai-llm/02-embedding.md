## 為什麼要學

「票」在詞表裡的代號是 2，「站」是 3，兩者只差 1。這能當成兩個詞很相近的證據嗎？不能。重新替全表編號並同步搬動模型裡的對應列，意思可以完全不變，代號的差卻會變。要找模型接下來操作的數值，得把索引當地址，去讀地址指到的那列。

## 一張能被訓練的表

詞嵌入（embedding）把離散索引換成固定寬度的向量。假設詞彙表有 4 個索引，隱藏維度（hidden size）是 3，嵌入矩陣就有 4 列，每列有 3 個可學習的數。讀取代號 2，不是拿整張表乘以 2，而是取出從 0 起算的第 2 號列。訓練時誤差能透過梯度改變這些參數，推論時只是讀已有的表。

輸入若含批次（batch）與序列 2 個軸，每個位置查一次，2 個軸都保留，最後多一個特徵軸。把形狀寫成「幾批裡的幾個位置，各拿幾個數」，比只背一串括號容易查錯。例如 2 筆各 3 個詞元、寬度 4，就是 2 × 3 × 4。最後那個 4 與詞表有幾列無關。

## 範例：替 2 張票取出特徵

這張表刻意讓索引 0 與 3 的數值比 0 與 1 更接近。把每筆輸入當一排抽屜號碼，觀察同一號碼出現兩次會發生什麼事。程式只做索引，所以不需要下載權重。

先用索引手動挑出一列，再核對程式的輸出維度。選中哪列和每列有幾個值，是不同問題。把下面的範例存成 `C:\dev\stackway-lab\llm` 裡的 `lookup_rows.py`。

在該目錄執行：Windows PowerShell 用 `py lookup_rows.py`；macOS／Linux 用 `python3 lookup_rows.py`。

```python
table = [[1, 0, 1], [-3, 4, 0], [2, 1, 0], [1, 0, 2]]
ids = [[0, 2], [3, 0]]
out = [[table[i] for i in row] for row in ids]
print(out)
print(len(out), len(out[0]), len(out[0][0]))
```

讀輸出時，先選第二筆（索引 1），再選它的第一個位置，此處拿到的是代號 3 的完整向量。若要多放一個新詞，應在表底加同寬的一列；如果改的是模型寬度，就得每列都增減特徵，下游原本吃 3 個數的層也要跟著改。前一種是「可查的東西更多」，後一種才是「每次交出去的表示不同」。

### 查表的參數有幾個？

請替玩具詞表算兩份數量：表裡有 4 列、每列 3 個數，所以模型要保存 12 個可學習的數值。這一批剛好有 4 個輸入位置，也交出 12 個特徵值，兩個數目相等只是巧合。若再加一筆長度同為 2 的句子，交出去的特徵值增加了，表裡的參數卻仍是原來那些。

反過來說，換成一張有更多列的詞表，但這次只輸入一個詞元，取出的仍然只是一列。預估模型本身多大，要看表的形狀；預估一批輸入會產生多大的中間結果，要看這批有幾個位置。

## 常見錯誤

不要把「同詞的輸入列相同」寫成「模型最後一定分不出語境」。這裡尚未加入位置與其他詞的訊息。下一堂[〈位置編碼與序列順序〉](#/lesson/ai-llm-03-position)會先處理位置；後面的區塊才讓「站」在不同句子裡取到不同的上下文。也不要替某一維硬取名叫「交通程度」；學到的座標未必對應人能命名的特性。

## 小結

檢查介面時先寫左右兩端：左邊是可查的整數索引，右邊是每個位置的一列實數。若形狀少了序列軸，先問是不是不小心把一整句平均了，而不是馬上更改詞表大小。
